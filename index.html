CASE_001 // MACHINE LEARNING · PRODUCTION

Customer Churn Prediction API

"Which customers are about to leave — and can a model warn us in time?"

Live on Vercel

The problem

Telecom companies lose revenue silently when subscribers churn. The business question is a classification problem: given a customer's usage and billing pattern, predict the probability they leave — early enough to act on it.

Approach

Cleaned and encoded the customer dataset, engineered features, and trained a scikit-learn classification pipeline. Judged it the honest way — ROC AUC and accuracy on held-out data, not training scores.

Implementation

The trained model was serialised and wrapped in a FastAPI service with /health and /predict endpoints, then deployed to Vercel. Getting it live meant diagnosing a real production bug: Vercel's rewrites were replacing the request path, so no route matched — fixed by removing the rewrites and letting native routing serve the endpoints.

Result

A live, publicly reachable ML API. Both endpoints were verified end-to-end after deployment — health check green, model loaded, and a test prediction returned exactly the value the local run produced.

CASE_002 // DEEP LEARNING · NEURAL NETWORKS

Anomaly Detection Autoencoder

"Teach a neural network what normal looks like — then let it point at everything that isn't."

Work in progress

The idea

An autoencoder is a neural network trained to copy its input to its output — through a narrow bottleneck. It can only succeed by learning the deep structure of normal data. Feed it something abnormal and the copy comes back wrong: that reconstruction error becomes an anomaly score.

Where it stands

The model and training code are built and public on GitHub. The hosted deployment previously failed and is being reworked — I'd rather label it honestly as in progress than dress it up as finished.

Why it matters

This is my bridge from classical ML into deep learning: the same discipline — data, training, honest evaluation — but now the features are learned by the network itself instead of engineered by hand.

What it detects

Any pattern that doesn't fit the learned shape of normal: fraud-like transactions, faulty sensor behaviour, defective items on a line — one technique, many domains.

HOW TO READ IT: the network compresses a signal down to a 2-node latent code, then rebuilds it. Normal data rebuilds cleanly. Anomalies don't — and the size of the error is the alarm.

How this site was built

You asked how this page was made — here is the honest recipe, step by step. No template, no page-builder, no copied code.

1

Design input, honestly sourced

ChatGPT was consulted for design direction, and its winning concept shapes this page: an "Intelligence Lab" — a personal engineering laboratory with an editorial finish, deliberately unlike the standard glowing-purple AI portfolio. Gemini was also asked, but its service was unavailable at the time (repeated server errors), and a Claude consultation was set up but its sign-in was never completed — so neither of those two contributed any idea here. The direction was then adapted and built by hand.

2

A design system before any layout

First the rules: the "Midnight Laboratory" palette (#101419 base, signal blue #65B9D8, muted green #A6B89D), Space Grotesk for headlines, IBM Plex Mono for technical labels, film grain over everything, and asymmetric layouts instead of centred template blocks.

3

The 3D Neural Core hero

Built with Three.js: a wireframe core wrapped in orbiting nodes, with connecting lines drawn between near neighbours — a living neural structure that leans toward your cursor as you move it.

4

Real projects, real numbers

The projects were written as case studies, and every metric on this page is genuine: ROC AUC 0.9355 and the 0.9533 test prediction come straight from the deployed churn model. The "Ping" button calls the actual live API — nothing is simulated.

5

Deep learning, drawn not photographed

The neural-network and autoencoder visuals are hand-built SVG diagrams — animated pulses through the layers, an encoder–decoder flow, and paired input/reconstruction bars — so the visuals explain the real mechanics instead of decorating the page.

6

Skills City in 3D

A second Three.js scene: seven labelled towers arranged around a plaza, with a low-poly engineering student standing at the centre. Raycasting detects which tower you tap; the selected tower rises and the readout panel prints its file.

7

One page, hand-assembled

Everything — markup, styling, both 3D scenes, the API call — is hand-written in a single HTML page, with the Three.js library bundled locally alongside it so the 3D never depends on a CDN being up. It was then tested at desktop and phone widths, section by section, before being published.

8

Honesty pass

Final check before shipping: no invented metrics, no fake "live" widgets, unfinished work labelled unfinished. What you read here is what actually exists.
